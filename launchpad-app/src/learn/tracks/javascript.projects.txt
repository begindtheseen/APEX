=== jsp-01 | To-do store 1: the data model
--- teach
This course is about building whole programs with everything the three JavaScript courses taught: closures and factories, classes, promises, generators, patterns, and the debugging habits that go with them. The first one is a **to-do store**: the part of a to-do app that holds the data and enforces the rules, with no screen attached. Over four lessons it gains commands, undo and redo, and saving. Each lesson's starter is the previous lesson's solution, so you are always extending working code — the way real software grows.

Every good module starts with three decisions, made before any code:

1. **The data model.** A to-do is `{ id, text, done }`. The store holds a list of them, in the order added.
2. **The invariants** — rules that must always be true. Ids are unique and **never reused**, even after a delete (otherwise an old reference could silently point at a new item). Text is never empty. `done` is always a boolean.
3. **The interface.** What callers can do: add, toggle, remove, list. Nothing else can touch the data.

A **factory function** gives you all three. The list lives in a closure, so the only way to change it is through the methods you return — and those methods are where the invariants are enforced.

```js
function createCounter() {
  let count = 0                   // private: only the methods below can see it
  return {
    increment() { count++ },
    value: () => count,
  }
}
const c = createCounter()
c.increment()
c.value()     // 1
```

Two habits separate a solid module from a leaky one:

- **Return copies, not your internal objects.** If `list()` hands out the real to-do objects, a caller can write `store.list()[0].done = 'maybe'` and break your invariants without calling any method. `todos.map((t) => ({ ...t }))` makes that impossible.
- **Fail loudly and specifically.** Removing an id that does not exist is a bug in the caller. Throwing `no todo with id 7` gets it fixed; silently doing nothing hides it.
--- task
Write `createTodoStore()`. It returns an object with:

- `add(text)` — trims `text`; throws `new Error('text is required')` if nothing is left. Otherwise adds `{ id, text, done: false }` with ids counting 1, 2, 3, … (never reused) and returns the new id.
- `toggle(id)` — flips `done`. Throws `new Error('no todo with id <id>')` if there is no such to-do.
- `remove(id)` — deletes the to-do, with the same error for an unknown id.
- `list(filter = 'all')` — copies of the to-dos in the order added: `'all'`, `'open'` (not done) or `'done'`. Any other filter throws an `Error`.

  return {

    toggle(id) {},
    remove(id) {},
    list(filter = 'all') {
      return todos
    },
  }
}
--- solution
function createTodoStore() {
  const todos = []
  let nextId = 1

  function find(id) {
    const todo = todos.find((t) => t.id === id)
    if (!todo) throw new Error(`no todo with id ${id}`)
    return todo
  }

  return {
    add(text) {
      const clean = String(text ?? '').trim()
      if (!clean) throw new Error('text is required')
      const todo = { id: nextId++, text: clean, done: false }
      todos.push(todo)
      return todo.id
    },
    toggle(id) {
      const todo = find(id)
      todo.done = !todo.done
    },
    remove(id) {
      const todo = find(id)
      todos.splice(todos.indexOf(todo), 1)
    },
    list(filter = 'all') {
      if (!['all', 'open', 'done'].includes(filter)) throw new Error(`unknown filter: ${filter}`)
      return todos
        .filter((t) => filter === 'all' || (filter === 'done' ? t.done : !t.done))
        .map((t) => ({ ...t }))
    },
  }
}

--- hint

--- hint

=== jsp-02 | To-do store 2: every change is a command
--- teach
Next the store will get undo and redo. Before writing a single line of undo, change the **shape** of the code so undo becomes easy. This is the **command pattern**: every change is an object that knows how to **do** itself and how to **undo** itself.

```js
function setColour(colour) {
  let previous
  return {
    do(state) { previous = state.colour; state.colour = colour },
    undo(state) { state.colour = previous },
  }
}
const state = { colour: 'red' }
const cmd = setColour('blue')
cmd.do(state)
state.colour     // 'blue'
cmd.undo(state)
state.colour     // 'red'
```

The key idea: a command **remembers whatever it needs to reverse itself**, and it captures that information when it runs, not when it is created. A remove command remembers the item it removed *and the position it was at*, so undo can put it back in exactly the same place. An add command remembers the id it assigned, so that doing it again (redo) recreates the same to-do rather than a new one with a different id.

The store then becomes a thin shell: each public method builds a command and passes it to one `execute(command)` function, which runs it and records it in a **history** list. All the knowledge about how to change things lives in the commands; the store only coordinates.

Refactoring like this is a design skill in itself. The public behaviour does not change at all — every check from the last lesson must still pass — while the inside is rearranged so the next feature is a small addition instead of a rewrite. Validate when the command is **created** (empty text) or at the start of `do` (unknown id), before anything changes, so a failed command never half-happens and never lands in the history.
--- task
Starting from your store, write three command factories. Each takes its arguments and returns `{ do(state), undo(state) }`, where `state` is `{ todos, nextId }`:

- `addCommand(text)` — throws `'text is required'` straight away for empty text. `do` adds the to-do (taking `state.nextId++` the first time, and reusing that same id if done again) and returns the id; `undo` removes it.
- `toggleCommand(id)` — `do` and `undo` both flip `done`.
- `removeCommand(id)` — `do` removes the to-do, remembering it and its position; `undo` puts it back at that position.

Unknown ids throw `'no todo with id <id>'` from `do`. Then rebuild `createTodoStore()` on top of them: keep `state` inside, route `add`, `toggle` and `remove` through an `execute(command)` that runs `do` and pushes the command onto a history list, and add `historySize()` — how many commands have succeeded. Everything from the last lesson must still work.

  return i

function addCommand(text) {
  const clean = cleanText(text)
  let id = null
  return {
    do(state) {
      if (id === null) id = state.nextId++
      state.todos.push({ id, text: clean, done: false })
      return id
    },
    undo(state) {
      state.todos.splice(findIndex(state, id), 1)
    },
  }
}

function toggleCommand(id) {
  const flip = (state) => {
    const todo = state.todos[findIndex(state, id)]
    todo.done = !todo.done
  }
  return { do: flip, undo: flip }
}

function removeCommand(id) {
  let index = -1
  let removed = null
  return {
    do(state) {
      index = findIndex(state, id)
      removed = state.todos.splice(index, 1)[0]
    },
    undo(state) {
      state.todos.splice(index, 0, removed)
    },
  }
}

function createTodoStore() {
  const state = { todos: [], nextId: 1 }
  const history = []

  function execute(command) {
    const result = command.do(state)
    history.push(command)
    return result
  }

  return {
    add: (text) => execute(addCommand(text)),
    toggle: (id) => execute(toggleCommand(id)),
    remove: (id) => execute(removeCommand(id)),
    list(filter = 'all') {
      if (!['all', 'open', 'done'].includes(filter)) throw new Error(`unknown filter: ${filter}`)
      return state.todos
        .filter((t) => filter === 'all' || (filter === 'done' ? t.done : !t.done))
        .map((t) => ({ ...t }))
    },
    historySize: () => history.length,
  }
}

=== jsp-03 | To-do store 3: undo and redo
--- teach
With every change already a command, undo and redo are two stacks and a few lines.

- **Undo**: pop the last command off the history, call its `undo`, and push it onto a **redo** stack.
- **Redo**: pop from the redo stack, call `do` again, and push it back onto the history.
- **Any new change clears the redo stack.** If you undo "add milk", then add "eggs", redoing "add milk" would replay a change on top of a state it was never made for. Every editor you have used behaves this way: type after undoing, and the redo is gone.

```
history: [add a, add b]   redo: []
undo  →  history: [add a]          redo: [add b]
redo  →  history: [add a, add b]   redo: []
undo, then add c
      →  history: [add a, add c]   redo: []     (add b is gone for good)
```

This is why the design work in the last lesson mattered: the commands already remember what they need, so undoing a remove really does put the to-do back **in its old position**, and redoing an add recreates it **with its old id**. Notice too what does *not* happen: an undone add does not give its id back. Ids are never reused, so after "add, undo, add" the second to-do gets id 2 — which keeps any saved reference to id 1 from silently pointing at a different to-do.

Return `true` or `false` from `undo` and `redo` to say whether anything happened, and offer `canUndo()` / `canRedo()` so a user interface can grey out its buttons. It is tempting to throw when there is nothing to undo, but pressing undo on an empty history is a normal thing for a user to do, not a bug.
--- task
Add to the store:

- `undo()` — undoes the most recent change still in the history and returns `true`, or returns `false` if there is nothing to undo.
- `redo()` — re-does the most recently undone change and returns `true`, or `false` if there is nothing to redo.
- `canUndo()` and `canRedo()` — booleans.

Any successful new change (add, toggle or remove) empties the redo stack. Undo and redo must restore the exact previous state: positions, ids and `done` flags.

function createTodoStore() {
  const state = { todos: [], nextId: 1 }
  const history = []
  const undone = []

  function execute(command) {
    const result = command.do(state)
    history.push(command)
    undone.length = 0
    return result
  }

  return {
    add: (text) => execute(addCommand(text)),
    toggle: (id) => execute(toggleCommand(id)),
    remove: (id) => execute(removeCommand(id)),
    list(filter = 'all') {
      if (!['all', 'open', 'done'].includes(filter)) throw new Error(`unknown filter: ${filter}`)
      return state.todos
        .filter((t) => filter === 'all' || (filter === 'done' ? t.done : !t.done))
        .map((t) => ({ ...t }))
    },
    historySize: () => history.length,
    undo() {
      const command = history.pop()
      if (!command) return false
      command.undo(state)
      undone.push(command)
      return true
    },
    redo() {
      const command = undone.pop()
      if (!command) return false
      command.do(state)
      history.push(command)
      return true
    },
    canUndo: () => history.length > 0,
    canRedo: () => undone.length > 0,
  }
}

=== jsp-04 | To-do store 4: renaming, saving and loading
--- teach
Two last features finish the store, and each tests the design from a different side.

**Renaming** is a new kind of change. With the command pattern, adding it touches nothing that exists: write `renameCommand(id, text)` — it remembers the old text when it runs, and puts it back on undo — and add one line to the store. Undo and redo work for it immediately. That is the payoff of the pattern: new features are additions, not edits.

**Saving** is about the boundary between your program and the outside world. `JSON.stringify` turns the state into text you could put in a file or `localStorage`; loading turns the text back into state. Decide deliberately what belongs in a save:

- The to-dos, obviously.
- `nextId` too — **not** "the largest id plus one". If you delete the newest to-do and reload, recomputing from the remaining ids would hand out a deleted id again and break the never-reused rule.
- **Not** the undo history. Commands are objects full of functions and closures; they do not survive JSON, and "undo" after a reload would mean something strange anyway.

Loading is where you must be **defensive**. The text may be from an old version, hand-edited, or truncated:

```js
function safeParse(text) {
  try {
    return JSON.parse(text)
  } catch {
    return null
  }
}
safeParse('{"ok": true}')   // { ok: true }
safeParse('{"ok": tr')      // null
```

Parsing is not enough: check the **shape** — an object, with an array of to-dos, each with the right types, and an integer `nextId`. If anything is wrong, throw one clear error rather than letting a half-valid object into the store to cause confusing failures later. And copy what you load field by field, so unknown extra fields in the file do not leak into your state.
--- task
Add:

- `renameCommand(id, text)` — throws `'text is required'` for empty text when created; `do` sets the trimmed text (throwing `'no todo with id <id>'` for an unknown id) and `undo` restores the old text. The store gets `rename(id, text)`, undoable like the others.
- `save()` — returns a JSON string of `{ todos, nextId }` (no history).
- `createTodoStore(saved)` — with no argument, an empty store as before; given a string from `save()`, a store with that state and an empty history. If the text is not valid JSON, or is not an object with a `todos` array (each with an integer `id`, a string `text` and a boolean `done`) and an integer `nextId`, throw `new Error('corrupt save')`.

=== jsp-05 | Adventure engine 1: a state machine
--- teach
The second build is a text-adventure engine. Underneath any game, wizard, checkout flow, network protocol or traffic light is the same structure: a **finite state machine**. You will build a reusable one first, then the game on top of it.

A state machine has:

- a set of **states** — exactly one of which is current (a door is `closed`, `open` or `locked`);
- **events** that can happen (`OPEN`, `CLOSE`, `LOCK`, `UNLOCK`);
- **transitions**: in state X, event E moves you to state Y. An event with no transition in the current state is simply ignored.

The powerful move is to write the machine as **data**:

```js
const door = {
  initial: 'closed',
  states: {
    closed: { on: { OPEN: 'open', LOCK: 'locked' } },
    open: { on: { CLOSE: 'closed' } },
    locked: { on: { UNLOCK: 'closed' } },
  },
}
```

Compare this with a tangle of booleans — `isOpen`, `isLocked` — where nothing stops both being true. A state machine makes **impossible states impossible**: there is no way to be open and locked at once, because there is no such state. And an illegal action (opening a locked door) cannot happen, because there is no transition for it.

A generic engine reads the config and does the bookkeeping: tracks the current state, looks up transitions, and **validates the config when the machine is created**. A typo in a target state name should fail immediately with a clear message, not strand a player in a state that does not exist three hours into a game. That habit — checking configuration up front — pays off in every data-driven system you will build.

One detail: look transitions up with `Object.hasOwn(on, event)`, not `on[event]`. Otherwise an event called `toString` or `constructor` finds something on `Object.prototype`.

=== jsp-06 | Adventure engine 2: guards, actions and context
--- teach
Plain transitions cannot express rules like "you can only open the vault **if you have the key**" or "after three wrong passwords, lock the account". Real state machines add three things.

**Context** — data that travels with the machine: a count of attempts, coins inserted, an inventory. The *state* says which mode you are in; the *context* holds the numbers.

**Guards** — a transition can carry a `guard(context, payload)` function. The transition is only taken if the guard returns something truthy. `send` gains a second argument, the event's **payload** (the password typed, the coin's value), which guards and actions receive.

**Actions** — a transition can carry an `action(context, payload)` that runs when the transition is taken: increment a counter, record a time. Because guards and actions are optional, call them with optional chaining: `t.action?.(ctx, payload)` calls `action` only if the transition has one.

A transition can therefore be written three ways, and a good engine accepts all of them by **normalising** them into one form before doing anything else:

```js
const forms = [
  'open',                                                  // a plain target
  { target: 'open', guard: (ctx) => ctx.hasKey },          // one guarded transition
  [{ target: 'in', guard: (c, p) => p === 'secret' }, { target: 'out' }],   // options
]
```

With an **array**, the engine tries the options in order and takes the **first whose guard passes** (an option without a guard always passes). That is how you write "if the password is right, log in; otherwise, if too many attempts, lock; otherwise stay out" as pure data.

States can have an **`enter(context, payload)` hook** too, run whenever the machine enters that state — including the initial state when the machine is created, and including a transition from a state back to itself.

Two design points. The machine should **copy** the context it is given, so two machines built from one config never share counters. And the order of operations should be predictable and documented: pick the transition (guards), run its action, change state, then run the new state's `enter`.
--- task

- when a transition is taken: run its `action(context, payload)`, change state, then run the new state's `enter(context, payload)` if it has one. The initial state's `enter(context)` runs when the machine is created.
- `can(event, payload)` — `true` if some option would be taken.
- a `context` getter returns the machine's context, which starts as a shallow **copy** of the one in the config.
- creation still validates every target, in every form.

function createMachine({ initial, states, context = {} }) {
  const known = (name) => Object.hasOwn(states, name)
  const options = (transition) =>
    (Array.isArray(transition) ? transition : [transition]).map((t) => (typeof t === 'string' ? { target: t } : t))

  if (!known(initial)) throw new Error(`unknown state: ${initial}`)
  for (const def of Object.values(states)) {
    for (const transition of Object.values(def.on ?? {})) {
      for (const { target } of options(transition)) {
        if (!known(target)) throw new Error(`unknown state: ${target}`)
      }
    }
  }

  const ctx = { ...context }
  let current = initial
  const visited = [initial]
  states[initial].enter?.(ctx)

  function pick(event, payload) {
    const on = states[current].on ?? {}
    if (!Object.hasOwn(on, event)) return null
    return options(on[event]).find((t) => !t.guard || t.guard(ctx, payload)) ?? null
  }

  return {
    get state() {
      return current
    },
    get context() {
      return ctx
    },
    can: (event, payload) => pick(event, payload) !== null,
    send(event, payload) {
      const t = pick(event, payload)
      if (t) {
        t.action?.(ctx, payload)
        current = t.target
        visited.push(current)
        states[current].enter?.(ctx, payload)
      }
      return current
    },
    history: () => [...visited],
  }
}

=== jsp-07 | Adventure engine 3: the game
--- teach
Now the payoff: a playable game in which the machine does the hard part. Map the game onto it:

- each **room** is a **state**;
- each **direction** (`north`, `east`, …) is an **event**;
- each room's **exits** are its transitions.

So "go north" is just `machine.send('north')`, and "is there an exit north?" is `machine.can('north')`. The engine you wrote has no idea it is running a game — which is exactly what makes it reusable.

The game layer adds what is specific to adventures:

**A command parser.** Players type loosely: `"  GO   North "`. Normalise first — trim, lowercase, collapse runs of spaces — then split into a verb and the rest:

```js
const words = '  GO   North '.trim().toLowerCase().split(/\s+/)
words     // ['go', 'north']
```

Map verbs to handlers, and answer anything else with a helpful message instead of crashing.

**World state.** Items lie in rooms and move into the player's inventory. The world description passed in is **data you do not own**: copy each room's item list when the game starts, rather than splicing items out of the caller's arrays. Otherwise starting a second game — or a test — finds the lamp already gone.

**Text output.** Each command returns the text to show. Keep the formatting in one `look()` function so every room is described the same way; consistency is what makes a text interface pleasant.

Building a game on top of a general engine — instead of writing one long `if` ladder over room names — is the same move as building a web app on a framework: the engine handles *how* things change, and your code describes *what* your particular world is.

--- teach
The last step turns a walking simulator into a game: obstacles and a goal. Both fall out of the machine's features rather than needing special cases in the game.

**Locked doors are guards.** An exit can now be written as `{ to: 'garden', requires: 'key' }`. When you build the machine, turn it into a guarded transition:

```js
const inventory = ['lamp']

```

Designing a program so its state can be observed directly, not only through printed text, is one of the most useful habits for making code testable.

=== jsp-09 | Report pipeline 1: parsing CSV properly
--- teach
The third build is a data pipeline: read a CSV export of sales, check it, summarise it, and print a report. Pipelines like this — parse, validate, transform, present — are a large share of all the code written anywhere, and each stage is a small, testable function.

It starts with a trap. CSV *looks* like "split on newlines, then split on commas":

```js
'a,b\n1,2'.split('\n').map((line) => line.split(','))   // [['a', 'b'], ['1', '2']]
```

That works until real data arrives. The CSV format lets a field be wrapped in **double quotes**, and inside quotes:

- a comma is just a character: `"Lovelace, Ada"` is one field;
- a newline is just a character: a quoted address can span lines;
- a double quote is written twice: `"She said ""hi"""` means `She said "hi"`.

Also, files from Windows end lines with `\r\n`, and most files end with a final newline that does not start a new row.

Splitting cannot handle any of that, because whether a comma matters depends on what came **before** it. The right tool is a tiny **state machine** walking the text one character at a time, with one flag: am I inside quotes?

- Outside quotes: `,` ends the field; `\n` ends the field and the row; `"` enters quotes; `\r` is ignored; anything else is added to the field.
- Inside quotes: `""` adds one `"`; a single `"` leaves quotes; anything else — commas and newlines included — is added to the field.

At the end, if you are still inside quotes, the file is broken: say so with an error rather than guessing. And be careful about the last row: text that does not end with a newline still has a final row to add, but a trailing newline must not produce an extra empty one.

One pass over the characters, building strings as you go, is linear — fine for files of hundreds of thousands of rows.
--- task
Write `parseCSV(text)` returning an array of rows, each an array of field strings:

- fields are separated by `,` and rows by `\n` or `\r\n`;
- a field in double quotes may contain commas, newlines and `""` (meaning one `"`);
- empty fields are kept (`a,,b` has three fields);
- a trailing newline does not add an empty row, and empty text gives `[]`;
- a quote that is never closed throws `new SyntaxError('unterminated quote')`.

function parseCSV(text) {
  const rows = []
  let row = []
  let field = ''
  let inQuotes = false
  let started = false
  for (let i = 0; i < text.length; i++) {
    const c = text[i]
    if (inQuotes) {
      if (c === '"' && text[i + 1] === '"') {
        field += '"'
        i++
      } else if (c === '"') {
        inQuotes = false
      } else {
        field += c
      }
    } else if (c === '"') {
      inQuotes = true
      started = true
    } else if (c === ',') {
      row.push(field)
      field = ''
      started = true
    } else if (c === '\n') {
      row.push(field)
      rows.push(row)
      row = []
      field = ''
      started = false
    } else if (c !== '\r') {
      field += c
      started = true
    }
  }
  if (inQuotes) throw new SyntaxError('unterminated quote')
  if (started) {
    row.push(field)
    rows.push(row)
  }
  return rows
}

--- hint

--- hint
Track whether the current row has started (any character, quote or comma seen). After the loop, push the last field and row only if it has.

=== jsp-10 | Report pipeline 2: from rows to typed records
--- teach
`parseCSV` gives you strings. The rest of the program wants **records** — `{ date: '2026-01-05', units: 10, price: 2.5 }` — with real numbers, and it wants to know which rows were bad. This is the **validation boundary**: the one place where untrusted text becomes trusted data. Everything after it can assume the data is clean, which keeps the rest of the pipeline simple.

Drive the conversion with a **schema** — data describing the columns you need and their types:

```js
const schema = { date: 'date', region: 'string', units: 'int', price: 'number' }
Object.entries(schema)    // [['date', 'date'], ['region', 'string'], …]
```

A schema beats hand-written code per column: adding a column is one line, and the same converter works for any file.

Design decisions worth making explicitly:

- **Find columns by header name, not position.** Exports reorder columns and add new ones. Read the header row, trim the names, and look each schema column up; ignore columns you do not need. A *required* column that is missing is not a bad row — the whole file is unusable — so throw.
- **Be strict about types.** `Number('')` is `0` and `Number(' 12 ')` is `12`, and `parseInt('12abc')` is `12`. Decide what you accept: here, trim the field, then an `int` must be all digits (with an optional minus sign), a `number` must convert to a finite number, and a `date` must be `YYYY-MM-DD` **and** a real day (no 30th of February).
- **Collect errors, do not stop at the first.** A report that dies on row 3 of 50,000 is useless. Record `{ row, message }` for each bad row and carry on, so a person can fix every problem in one pass. Number rows as a spreadsheet would: the header is row 1, the first data row is row 2.
- **Skip blank lines** quietly — they are formatting, not data.

A message like `units: "1.5" is not a valid int` names the column, shows the offending value in quotes (so stray spaces are visible), and says what was expected.

const INVALID = Symbol('invalid')

function parseValue(type, raw) {
  switch (type) {
    case 'string':
      return raw
    case 'int':
      return /^-?\d+$/.test(raw) ? Number(raw) : INVALID
    case 'number':
      return raw !== '' && Number.isFinite(Number(raw)) ? Number(raw) : INVALID
    case 'date': {
      const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(raw)
      if (!m) return INVALID
      const d = new Date(Date.UTC(Number(m[1]), Number(m[2]) - 1, Number(m[3])))
      return d.getUTCMonth() === Number(m[2]) - 1 && d.getUTCDate() === Number(m[3]) ? raw : INVALID
    }
    default:
      throw new Error(`unknown type: ${type}`)
  }
}

function toRecords(rows, schema) {
  if (rows.length === 0) return { records: [], errors: [] }
  const header = rows[0].map((h) => h.trim())
  const index = {}
  for (const column of Object.keys(schema)) {
    const i = header.indexOf(column)
    if (i < 0) throw new Error(`missing column: ${column}`)
    index[column] = i
  }
  const records = []
  const errors = []
  rows.slice(1).forEach((cells, k) => {
    const row = k + 2
    if (cells.length === 1 && cells[0].trim() === '') return
    if (cells.length !== header.length) {
      errors.push({ row, message: `expected ${header.length} fields, got ${cells.length}` })
      return
    }
    const record = {}
    for (const [column, type] of Object.entries(schema)) {
      const raw = cells[index[column]].trim()
      const value = parseValue(type, raw)
      if (value === INVALID) {
        errors.push({ row, message: `${column}: "${raw}" is not a valid ${type}` })
        return
      }
      record[column] = value
    }
    records.push(record)
  })
  return { records, errors }
}

=== jsp-11 | Report pipeline 3: grouping and totals
--- teach
With clean records, the pipeline can answer questions: revenue by region, units by product, sales by month. That is **aggregation**, and it is the frequency-counting pattern you already know, with a small object per group instead of a number.


Design choices that make the function reusable:

- **Group by a field name *or* a function.** `summarize(records, 'region')` is the common case, but `summarize(records, (r) => r.date.slice(0, 7))` gives sales by month with no new code. Accepting both is one line: turn a string into `(r) => r[by]`.
- **Money in integer cents.** Revenue is `units × price`, summed over many rows. With decimal numbers, those sums drift (`0.1 + 0.2` is not `0.3`), and a report whose columns do not add up to its total destroys trust in everything else on the page. Convert each price to cents once — `Math.round(price * 100)` — multiply by units, and add integers. Convert back to dollars only when displaying.
- **Deterministic order.** Sort by revenue, highest first, and break ties by the key. Without a tie-break, two regions with equal revenue could swap places between runs or machines, and a diff of two reports shows a change that is not there.

Keep `totals(records)` separate from `summarize`: the grand total should be computed from the records, not by adding up the rounded group rows — the same principle as above, one exact source for every number.

const cents = (price) => Math.round(price * 100)

function summarize(records, by) {
  const keyOf = typeof by === 'function' ? by : (r) => r[by]
  const groups = new Map()
  for (const r of records) {
    const key = keyOf(r)
    if (!groups.has(key)) groups.set(key, { key, orders: 0, units: 0, revenue: 0 })
    const g = groups.get(key)
    g.orders++
    g.units += r.units
    g.revenue += cents(r.price) * r.units
  }
  return [...groups.values()].sort((a, b) => b.revenue - a.revenue || (a.key < b.key ? -1 : a.key > b.key ? 1 : 0))
}

function totals(records) {
  return records.reduce(
    (t, r) => ({ orders: t.orders + 1, units: t.units + r.units, revenue: t.revenue + cents(r.price) * r.units }),
    { orders: 0, units: 0, revenue: 0 },
  )
}

function parseCSV(text) {
  const rows = []
  let row = []
  let field = ''
  let inQuotes = false
  let started = false
  for (let i = 0; i < text.length; i++) {
    const c = text[i]
    if (inQuotes) {
      if (c === '"' && text[i + 1] === '"') {
        field += '"'
        i++
      } else if (c === '"') {
        inQuotes = false
      } else {
        field += c
      }
    } else if (c === '"') {
      inQuotes = true
      started = true
    } else if (c === ',') {
      row.push(field)
      field = ''
      started = true
    } else if (c === '\n') {
      row.push(field)
      rows.push(row)
      row = []
      field = ''
      started = false
    } else if (c !== '\r') {
      field += c
      started = true
    }
  }
  if (inQuotes) throw new SyntaxError('unterminated quote')
  if (started) {
    row.push(field)
    rows.push(row)
  }
  return rows
}

const INVALID = Symbol('invalid')

function parseValue(type, raw) {
  switch (type) {
    case 'string':
      return raw
    case 'int':
      return /^-?\d+$/.test(raw) ? Number(raw) : INVALID
    case 'number':
      return raw !== '' && Number.isFinite(Number(raw)) ? Number(raw) : INVALID
    case 'date': {
      const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(raw)
      if (!m) return INVALID
      const d = new Date(Date.UTC(Number(m[1]), Number(m[2]) - 1, Number(m[3])))
      return d.getUTCMonth() === Number(m[2]) - 1 && d.getUTCDate() === Number(m[3]) ? raw : INVALID
    }
    default:
      throw new Error(`unknown type: ${type}`)
  }
}

function toRecords(rows, schema) {
  if (rows.length === 0) return { records: [], errors: [] }
  const header = rows[0].map((h) => h.trim())
  const index = {}
  for (const column of Object.keys(schema)) {
    const i = header.indexOf(column)
    if (i < 0) throw new Error(`missing column: ${column}`)
    index[column] = i
  }
  const records = []
  const errors = []
  rows.slice(1).forEach((cells, k) => {
    const row = k + 2
    if (cells.length === 1 && cells[0].trim() === '') return

        errors.push({ row, message: `${column}: "${raw}" is not a valid ${type}` })
        return
      }

    }
    records.push(record)
  })

}

function formatTable(rows, columns) {
  const cells = rows.map((r) => columns.map((c) => (c.format ? c.format(r[c.key]) : String(r[c.key]))))
  const widths = columns.map((c, j) => Math.max(c.title.length, ...cells.map((row) => row[j].length)))
  const line = (values) =>
    values
      .map((v, j) => (columns[j].align === 'right' ? v.padStart(widths[j]) : v.padEnd(widths[j])))
      .join('  ')
      .trimEnd()
  return [line(columns.map((c) => c.title)), line(widths.map((w) => '-'.repeat(w))), ...cells.map(line)].join('\n')
}

    { key: 'revenue', title: 'revenue', align: 'right', format: money },

    for (const e of errors) out.push(`  row ${e.row}: ${e.message}`)
  }

=== jsp-13 | Capstone: a spreadsheet engine
--- teach
From here on there are no step-by-step lessons: each capstone is a **specification**, an almost empty editor, and checks that test behaviour only. How you structure the code is up to you. This is the real skill — turning a written spec into a working program on your own.

A method that works for any spec:

1. **Read it twice**, then write the list of behaviours as a checklist, including every error case.
2. **Design the data** before the code. What do you store? What do you compute on demand?
3. **Build the thinnest slice first** — here: plain numbers in and out — and try it with `console.log` before adding anything.
4. **Grow it one behaviour at a time**, re-running your earlier experiments as you go.
5. **Do the error cases last**, but do all of them.

For this capstone, some things to think about (not a recipe):

- **Store what the user typed, compute values when asked.** Then recalculation is automatic: change A1, and the next time anyone asks for A3, it is computed from the new A1.
- A formula is a small expression language. You have written a tokenizer and a recursive-descent parser before (in the expert course); the same shape works here, with cell references as a kind of token.
- **Circular references** (A1 is `=B1`, B1 is `=A1`) would recurse for ever. Keep track of the cells you are in the middle of evaluating; meeting one of them again means a cycle.
- **Repeated references.** If A2 is `=A1+A1`, A3 is `=A2+A2`, and so on, re-evaluating every reference from scratch doubles the work at each step — forty cells would take a trillion evaluations. Remember each cell's value for the duration of one `get`.
- **Errors are values.** In a spreadsheet, `=1/0` does not crash; the cell *shows* `#DIV/0!`, and any cell that uses it shows the same error. Representing errors in a way you cannot confuse with text makes propagation easy.
--- task
Write `createSheet()`, returning `{ set(ref, input), get(ref) }`.

**Cells** are a column letter `A`–`Z` and a row `1`–`999` (`B7`, `Z999`), case-insensitive. `set` or `get` with anything else throws an `Error`.

**`set(ref, input)`** stores the text the user typed. An empty (or all-space) input clears the cell.

**`get(ref)`** returns the cell's current value:
- empty → `null`;
- input that is a number (optional `-`, digits, optional `.` and digits; surrounding spaces allowed) → that number;
- input starting with `=` → the formula's result;
- anything else → the text itself.

**Formulas** contain numbers, cell references, `+ - * /` with the usual precedence, parentheses, unary minus, and the functions `SUM`, `AVG`, `MIN` and `MAX`. Function arguments are separated by commas and may be expressions or ranges like `A1:B3` (every cell in the rectangle). References are case-insensitive and spaces are allowed.
- In arithmetic an empty cell counts as `0`; a text cell gives `#VALUE!`.
- In a range, only number cells count; empty and text cells are skipped. `SUM` of nothing is 0, `MIN`/`MAX` of nothing is 0, `AVG` of nothing is `#DIV/0!`.

**Errors** are returned by `get` as strings: `#DIV/0!` (division by zero), `#VALUE!` (text used in arithmetic), `#CYCLE!` (the cell is part of, or depends on, a circular reference), `#NAME?` (an unknown function) and `#ERROR!` (a formula that does not parse). A formula that uses a cell holding an error has that same error.

Values always reflect the current inputs, and `get` must stay fast even when cells refer to other cells many times over.

const CELL = /^([A-Z])([1-9]\d{0,2})$/

class CellError extends Error {
  constructor(code) {
    super(code)
    this.code = code
  }
}

function createSheet() {
  const inputs = new Map()

  function normalize(ref) {
    const r = String(ref).trim().toUpperCase()
    if (!CELL.test(r)) throw new Error(`bad reference: ${ref}`)
    return r
  }

  function set(ref, input) {
    const r = normalize(ref)
    const text = String(input ?? '')
    if (text.trim() === '') inputs.delete(r)
    else inputs.set(r, text)
  }

  function tokenize(src) {
    const tokens = []
    const re = /\s*(?:(\d+(?:\.\d+)?)|([A-Z]+\d*)|([-+*/(),:]))/y
    let i = 0
    while (i < src.length) {
      if (/^\s*$/.test(src.slice(i))) break
      re.lastIndex = i
      const m = re.exec(src)
      if (!m) throw new CellError('#ERROR!')
      i = re.lastIndex
      if (m[1] !== undefined) tokens.push({ type: 'num', value: Number(m[1]) })
      else if (m[2] !== undefined) tokens.push({ type: CELL.test(m[2]) ? 'ref' : 'name', value: m[2] })
      else tokens.push({ type: 'op', value: m[3] })
    }
    tokens.push({ type: 'end' })
    return tokens
  }

  function rangeRefs(a, b) {
    const [, ca, ra] = CELL.exec(a)
    const [, cb, rb] = CELL.exec(b)
    const [c1, c2] = [ca.charCodeAt(0), cb.charCodeAt(0)].sort((x, y) => x - y)
    const [r1, r2] = [Number(ra), Number(rb)].sort((x, y) => x - y)
    const refs = []
    for (let r = r1; r <= r2; r++) for (let c = c1; c <= c2; c++) refs.push(String.fromCharCode(c) + r)
    return refs
  }

  function evaluate(ref, memo, stack) {
    if (memo.has(ref)) return memo.get(ref)
    if (stack.has(ref)) throw new CellError('#CYCLE!')
    const raw = inputs.get(ref)
    let value
    if (raw === undefined) value = null
    else if (/^\s*-?\d+(\.\d+)?\s*$/.test(raw)) value = Number(raw)
    else if (!raw.startsWith('=')) value = raw
    else {
      stack.add(ref)
      try {
        value = formula(raw.slice(1).toUpperCase(), memo, stack)
      } catch (err) {
        if (!(err instanceof CellError)) throw err
        value = err
      } finally {
        stack.delete(ref)
      }
    }
    memo.set(ref, value)
    return value
  }

  function formula(src, memo, stack) {
    const tokens = tokenize(src)
    let pos = 0
    const peek = () => tokens[pos]
    const isOp = (v) => peek().type === 'op' && peek().value === v
    const expect = (v) => {
      if (!isOp(v)) throw new CellError('#ERROR!')
      pos++
    }
    const cellValue = (ref) => {
      const v = evaluate(ref, memo, stack)
      if (v instanceof CellError) throw new CellError(v.code)
      return v
    }
    const asNumber = (v) => {
      if (v === null) return 0
      if (typeof v !== 'number') throw new CellError('#VALUE!')
      return v
    }

    function expr() {
      let v = term()
      while (isOp('+') || isOp('-')) {
        const op = tokens[pos++].value
        const r = term()
        v = op === '+' ? v + r : v - r
      }
      return v
    }
    function term() {
      let v = unary()
      while (isOp('*') || isOp('/')) {
        const op = tokens[pos++].value
        const r = unary()
        if (op === '/' && r === 0) throw new CellError('#DIV/0!')
        v = op === '*' ? v * r : v / r
      }
      return v
    }
    function unary() {
      if (isOp('-')) {
        pos++
        return -unary()
      }
      if (isOp('+')) {
        pos++
        return unary()
      }
      return atom()
    }
    function atom() {
      const t = peek()
      if (t.type === 'num') {
        pos++
        return t.value
      }
      if (t.type === 'ref') {
        pos++
        return asNumber(cellValue(t.value))
      }
      if (t.type === 'name') {
        pos++
        expect('(')
        const values = []
        if (!isOp(')')) {
          args(values)
          while (isOp(',')) {
            pos++
            args(values)
          }
        }
        expect(')')
        return call(t.value, values)
      }
      if (isOp('(')) {
        pos++
        const v = expr()
        expect(')')
        return v
      }
      throw new CellError('#ERROR!')
    }
    function args(values) {
      const t = peek()
      if (t.type === 'ref' && tokens[pos + 1].type === 'op' && tokens[pos + 1].value === ':') {
        const end = tokens[pos + 2]
        if (end.type !== 'ref') throw new CellError('#ERROR!')
        pos += 3
        for (const ref of rangeRefs(t.value, end.value)) {
          const v = cellValue(ref)
          if (typeof v === 'number') values.push(v)
        }
      } else {
        values.push(expr())
      }
    }
    function call(name, values) {
      switch (name) {
        case 'SUM':
          return values.reduce((a, b) => a + b, 0)
        case 'AVG':
          if (!values.length) throw new CellError('#DIV/0!')
          return values.reduce((a, b) => a + b, 0) / values.length
        case 'MIN':
          return values.length ? Math.min(...values) : 0
        case 'MAX':
          return values.length ? Math.max(...values) : 0
        default:
          throw new CellError('#NAME?')
      }
    }

    const result = expr()
    if (peek().type !== 'end') throw new CellError('#ERROR!')
    return result
  }

  function get(ref) {
    const v = evaluate(normalize(ref), new Map(), new Set())
    return v instanceof CellError ? v.code : v
  }

  return { set, get }
}

=== jsp-14 | Capstone: a rate-limited job queue
--- teach
Every system that talks to an API with limits needs this: a queue that runs jobs **concurrently, but not too concurrently**, respects a **rate limit**, lets urgent work jump ahead, and **retries** flaky failures. It combines almost everything from the advanced and expert courses: closures, promises, timers, the event loop and careful state management.

Before you code, think about the moving parts:

- **The waiting list.** Jobs wait until they can start. With priorities, "next" means the highest priority, and among equals, the one added first. A stable way to break ties is a sequence number given to each job as it is added.
- **When to start jobs.** There is one moment to try: whenever something changes — a job is added, a job finishes. Write one function (often called `pump` or `drain`) that starts as many waiting jobs as the limits allow, and call it from every such place.
- **The rate limit.** "At most `limit` starts in any `interval` ms" is a **sliding window**: keep the times of recent starts, forget those older than `interval`, and if `limit` remain, you must wait — until the oldest one leaves the window. That wait is a timer that calls `pump` again. Take care not to set a new timer every time `pump` runs.
- **Each job's promise.** `add` returns a promise, but the job may not start for a while. Store the promise's `resolve` and `reject` alongside the job, and call them when it finally settles.
- **Retries.** A failed job with attempts left goes back into the waiting list — keeping its priority and sequence, so it does not lose its place behind newer jobs.
- **Idle.** `onIdle()` resolves when nothing is running and nothing is waiting — useful for tests and for shutting down cleanly.

A job may be an `async` function, a function returning a plain value, or one that throws before returning a promise. Treat all three the same by starting it inside a promise chain.

function createQueue({ concurrency = 1, limit = Infinity, interval = 1000, retries = 0 } = {}) {
  const waiting = []
  const starts = []
  let idleWaiters = []
  let running = 0
  let done = 0
  let failed = 0
  let seq = 0
  let timer = null

  function nextIndex() {
    let best = 0
    for (let i = 1; i < waiting.length; i++) {
      const a = waiting[i]
      const b = waiting[best]
      if (a.priority > b.priority || (a.priority === b.priority && a.seq < b.seq)) best = i
    }
    return best
  }

  function checkIdle() {
    if (running === 0 && waiting.length === 0) {
      const resolvers = idleWaiters
      idleWaiters = []
      for (const resolve of resolvers) resolve()
    }
  }

  function start(task) {
    running++
    task.attempts++
    Promise.resolve()
      .then(() => task.job())
      .then(
        (value) => {
          running--
          done++
          task.resolve(value)
          pump()
        },
        (error) => {
          running--
          if (task.attempts <= retries) {
            waiting.push(task)
          } else {
            failed++
            task.reject(error)
          }
          pump()
        },
      )
  }

  function pump() {
    while (running < concurrency && waiting.length > 0) {
      const now = Date.now()
      while (starts.length && now - starts[0] >= interval) starts.shift()
      if (starts.length >= limit) {
        if (!timer) {
          timer = setTimeout(() => {
            timer = null
            pump()
          }, Math.max(1, starts[0] + interval - now))
        }
        return
      }
      const [task] = waiting.splice(nextIndex(), 1)
      if (limit !== Infinity) starts.push(now)
      start(task)
    }
    checkIdle()
  }

  return {
    add(job, { priority = 0 } = {}) {
      return new Promise((resolve, reject) => {
        waiting.push({ job, priority, seq: seq++, attempts: 0, resolve, reject })
        pump()
      })
    },
    onIdle() {
      if (running === 0 && waiting.length === 0) return Promise.resolve()
      return new Promise((resolve) => idleWaiters.push(resolve))
    },
    stats() {
      return { running, waiting: waiting.length, done, failed }
    },
  }
}

=== jsp-15 | Capstone: a template engine
--- teach
Template engines — Handlebars, Mustache, Liquid, the ones inside every static site generator — turn a template with placeholders and blocks into text. Building one exercises the full compiler pipeline on a friendly scale: **scan** the template into pieces, **build a tree** from the blocks, then **render** the tree against the data.

Things to think about before you start:

- **Scanning.** A template is literal text with tags between `{{` and `}}` (or `{{{` and `}}}`). Finding each next `{{` with `indexOf` and slicing the text between tags is simpler and faster than one enormous regex.
- **Blocks nest.** `{{#each}}` inside `{{#if}}` inside `{{#each}}` — so a flat list of pieces is not enough. Use a **stack**: an opening tag pushes a new block node, and its children are collected until the matching closing tag pops it. The stack also tells you when the template is malformed: a closing tag that does not match the top, or blocks still open at the end.
- **Scope.** Inside `{{#each people}}`, `{{name}}` means the current person's name, but `{{company}}` still means the outer `company`. Render with a **chain of scopes**: look a name up in the innermost scope first, then outwards.
- **Escaping.** Data often comes from users. Inserting `<script>` unescaped into an HTML page is a security hole (cross-site scripting). So the safe default escapes `& < > " '`, and printing raw HTML needs the deliberate, visibly different triple braces.
- **Truthiness.** In templates an empty list should count as false — `{{#if items}}` usually means "if there are any" — which is not JavaScript's rule, so decide it explicitly.

Write the scanner, then the tree builder, then the renderer, and test each with `console.log` as you go. Keeping the three stages separate is what keeps each one simple.
--- task

A missing value, `null` or `undefined` renders as nothing; `0` renders as `0`. Spaces inside the braces are allowed.
- `{{{ path }}}` — the same, but not escaped.
- `{{! anything }}` — a comment; renders as nothing.
- `{{#if path}} … {{else}} … {{/if}}` — the first part if the value is truthy, otherwise the `else` part (which is optional). An empty array counts as false.
- `{{#each path}} … {{/each}}` — the inner part once per item of the array (nothing if it is not an array). Inside, `{{this}}` is the item, `{{this.x}}` a property of it, `{{@index}}` its 0-based index, and a plain name is looked up on the item first, then in the enclosing scopes.
- Blocks nest. A block that is never closed, a closing tag that does not match, an `{{else}}` outside an `if` (or a second one), or a `{{` with no closing braces throws a `SyntaxError`.

const ESCAPES = { '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' }
const escapeHtml = (s) => s.replace(/[&<>"']/g, (c) => ESCAPES[c])

function parseTemplate(template) {
  const root = { type: 'root', children: [] }
  const stack = [{ node: root, target: root.children }]
  const top = () => stack[stack.length - 1]
  let i = 0
  while (i < template.length) {
    const open = template.indexOf('{{', i)
    if (open < 0) {
      top().target.push({ type: 'text', value: template.slice(i) })
      break
    }
    if (open > i) top().target.push({ type: 'text', value: template.slice(i, open) })
    const raw = template[open + 2] === '{'
    const closer = raw ? '}}}' : '}}'
    const close = template.indexOf(closer, open + (raw ? 3 : 2))
    if (close < 0) throw new SyntaxError(`unclosed tag at ${open}`)
    const tag = template.slice(open + (raw ? 3 : 2), close).trim()
    i = close + closer.length

    if (raw) {
      top().target.push({ type: 'var', path: tag, raw: true })
    } else if (tag.startsWith('!')) {
      // a comment: nothing to render
    } else if (tag.startsWith('#')) {
      const [kind, path = ''] = tag.slice(1).trim().split(/\s+/)
      if (kind !== 'if' && kind !== 'each') throw new SyntaxError(`unknown block {{#${kind}}}`)
      const node = { type: kind, path, children: [], otherwise: [] }
      top().target.push(node)
      stack.push({ node, target: node.children })
    } else if (tag.startsWith('/')) {
      const kind = tag.slice(1).trim()
      if (stack.length === 1 || top().node.type !== kind) throw new SyntaxError(`unexpected {{/${kind}}}`)
      stack.pop()
    } else if (tag === 'else') {
      const frame = top()
      if (frame.node.type !== 'if' || frame.target === frame.node.otherwise) throw new SyntaxError('unexpected {{else}}')
      frame.target = frame.node.otherwise
    } else {
      top().target.push({ type: 'var', path: tag, raw: false })
    }
  }
  if (stack.length > 1) throw new SyntaxError(`unclosed {{#${top().node.type}}}`)
  return root.children
}

function lookup(path, scopes) {
  const inner = scopes[scopes.length - 1]
  if (path === '@index') return inner.index
  const parts = path.split('.')
  let value
  if (parts[0] === 'this') {
    value = inner.value
    parts.shift()
  } else {
    const scope = [...scopes].reverse().find((s) => s.value !== null && typeof s.value === 'object' && parts[0] in s.value)
    if (!scope) return undefined
    value = scope.value
  }
  for (const part of parts) {
    if (value === null || value === undefined) return undefined
    value = value[part]
  }
  return value
}

function truthy(value) {
  return Array.isArray(value) ? value.length > 0 : Boolean(value)
}

function renderNodes(nodes, scopes) {
  let out = ''
  for (const node of nodes) {
    if (node.type === 'text') out += node.value
    else if (node.type === 'var') {
      const v = lookup(node.path, scopes)
      const text = v === null || v === undefined ? '' : String(v)
      out += node.raw ? text : escapeHtml(text)
    } else if (node.type === 'if') {
      out += renderNodes(truthy(lookup(node.path, scopes)) ? node.children : node.otherwise, scopes)
    } else if (node.type === 'each') {
      const list = lookup(node.path, scopes)
      if (Array.isArray(list)) {
        list.forEach((item, index) => {
          out += renderNodes(node.children, [...scopes, { value: item, index }])
        })
      }
    }
  }
  return out
}

function render(template, data) {
  return renderNodes(parseTemplate(template), [{ value: data, index: undefined }])
}

=== jsp-16 | Capstone: a bank
--- teach
The last capstone is a small **domain model**: a bank ledger. There is no clever algorithm here. The difficulty is the one that dominates real business software — getting **every rule** right, **every time**, with **no partial failures**.

Think about these before writing code:

- **Money.** Amounts arrive as text like `'12.50'`. Parse them into integer cents immediately, do all arithmetic in cents, and format back to text only on the way out. Decimal numbers would make balances drift.
- **Errors callers can act on.** A caller needs to tell "not enough money" from "no such account" — to show the right message, or to retry. A custom error class with a `code` property (`'INSUFFICIENT_FUNDS'`) is far better than matching on message text, which you will want to reword one day.
- **Validate everything, then change anything.** A transfer touches two accounts. If you take money out of the first and *then* discover the second is closed, you have destroyed money. Check every condition first; only when all pass, apply the changes. This is what "atomic" means, and it is the most important rule in the whole capstone.
- **A statement is an append-only log.** Each successful operation adds an entry recording what happened and the balance after it. Failed operations leave no trace. Hand out copies, so no caller can rewrite history.
- **State that only moves one way.** A closed account stays closed. Decide which operations still make sense on it — reading its balance and statement, yes; moving money, no.
- **Performance by design.** Keep the current balance stored and update it with each entry. Recomputing it from the whole statement on every call would make a busy account slower with every transaction.
--- task

- `deposit(id, amount)` and `withdraw(id, amount)` — return the new balance.
- `transfer(fromId, toId, amount)` — moves money between two accounts, atomically.
- `balance(id)` — the balance as a string with 2 decimals (`'12.50'`, `'-5.00'`).

class BankError extends Error {
  constructor(code, message = code) {
    super(message)
    this.name = 'BankError'
    this.code = code
  }
}

function toCents(amount) {
  const m = typeof amount === 'string' ? /^(\d+)(?:\.(\d{1,2}))?$/.exec(amount.trim()) : null
  if (!m) throw new BankError('INVALID_AMOUNT', `not an amount: ${amount}`)
  return Number(m[1]) * 100 + Number((m[2] ?? '').padEnd(2, '0'))
}

function formatCents(cents) {
  const sign = cents < 0 ? '-' : ''
  const abs = Math.abs(cents)
  return `${sign}${Math.floor(abs / 100)}.${String(abs % 100).padStart(2, '0')}`
}

function createBank() {
  const accounts = new Map()
  let nextId = 1

  function account(id) {
    const acc = accounts.get(id)
    if (!acc) throw new BankError('NO_ACCOUNT', `no account ${id}`)
    return acc
  }

  function openAccount(id) {
    const acc = account(id)
    if (acc.closed) throw new BankError('ACCOUNT_CLOSED', `account ${id} is closed`)
    return acc
  }

  function positive(amount) {
    const cents = toCents(amount)
    if (cents <= 0) throw new BankError('INVALID_AMOUNT', 'amount must be positive')
    return cents
  }

  function record(acc, type, cents, counterparty) {
    acc.balance += type === 'deposit' || type === 'transfer-in' ? cents : -cents
    const entry = { type, amount: formatCents(cents), balance: formatCents(acc.balance) }
    if (counterparty) entry.counterparty = counterparty
    acc.entries.push(entry)
  }

  function ensureFunds(acc, cents) {
    if (acc.balance - cents < -acc.overdraft) throw new BankError('INSUFFICIENT_FUNDS', `insufficient funds in ${acc.id}`)
  }

  return {
    open(owner, { overdraft = '0' } = {}) {
      if (typeof owner !== 'string' || owner.trim() === '') throw new BankError('INVALID_OWNER', 'owner is required')
      const id = `ACC-${nextId++}`
      accounts.set(id, { id, owner: owner.trim(), balance: 0, overdraft: toCents(overdraft), closed: false, entries: [] })
      return id
    },
    deposit(id, amount) {
      const acc = openAccount(id)
      record(acc, 'deposit', positive(amount))
      return formatCents(acc.balance)
    },
    withdraw(id, amount) {
      const acc = openAccount(id)
      const cents = positive(amount)
      ensureFunds(acc, cents)
      record(acc, 'withdrawal', cents)
      return formatCents(acc.balance)
    },
    transfer(fromId, toId, amount) {
      const from = account(fromId)
      const to = account(toId)
      if (fromId === toId) throw new BankError('SAME_ACCOUNT', 'cannot transfer to the same account')
      openAccount(fromId)
      openAccount(toId)
      const cents = positive(amount)
      ensureFunds(from, cents)
      record(from, 'transfer-out', cents, toId)
      record(to, 'transfer-in', cents, fromId)
    },
    balance: (id) => formatCents(account(id).balance),
    statement: (id) => account(id).entries.map((e) => ({ ...e })),
    close(id) {
      const acc = openAccount(id)
      if (acc.balance !== 0) throw new BankError('NONZERO_BALANCE', `account ${id} still holds money`)
      acc.closed = true
    },
    accounts: () => [...accounts.values()].map((a) => ({ id: a.id, owner: a.owner, balance: formatCents(a.balance), closed: a.closed })),
  }
}
--- hint
Store accounts in a `Map` by id: `{ id, owner, balance, overdraft, closed, entries }`, with balances and the overdraft in integer cents.

--- hint
One `record(account, type, cents, counterparty)` helper can update the balance and append the statement entry, so the two can never disagree.
